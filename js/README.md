# @thehappieco/kit

The Happie Co's shared cryptographic kit for the browser and Node: HPKE (RFC 9180, one fixed suite), the sealed envelope, the zero-knowledge account scheme (Argon2id, wraps, recovery codes), passkey PRF wraps, a key at rest in the browser, request signing, the Wappie profile with its platform wrap, the platform's account protocol (id-v1, parts 1 to 3: the account core, sealed key delivery and PKCE, and passkeys with PRF), and the relying party of the platform's id.

Import by subpath (`@thehappieco/kit/seal`, `/account`, `/kdf.worker`, `/hpke`, `/passkey`, `/browserAccount`, `/reqhmac`, `/jcs`, `/bytes`, `/errors`, `/profiles/wappie`, `/profiles/platform`, `/profiles/platform/core`, `/oidc-rp`). Every function of the generic modules takes a profile, the product's labels and prefixes, as its first argument. `/profiles/platform` is the platform's protocol itself: its functions take no profile. `/oidc-rp` takes the product's constants (issuer, client, redirect URI, scopes and key label) and keeps a delivered key only once the product's server has named it (`finishSignIn`). Nothing under `dist/internal/` is a subpath export.

Argon2id runs in the kit's KDF worker (`dist/kdf.worker.js`), which `/account` and `/profiles/platform` start where there are Workers, so a bundle that imports them emits that file. `/profiles/platform/core` is `/profiles/platform` without that default: it runs Argon2id in the worker `options.worker` makes, or on the calling thread, and a bundle that imports it, `/oidc-rp` or anything else emits no worker. With Vite, `import KDFWorker from '@thehappieco/kit/kdf.worker?worker'` and `{ worker: () => new KDFWorker() }` give the core entry the kit's worker. The page speaks version 2 of the worker's protocol: a hello answered with `{ready: true, v: 2}` before the password is sent as a transferred copy, the bounds checked again in the worker, and a refusal (`out_of_bounds`, `unsupported_alg`) told apart from a failure (`kdf_failed`); a worker that does not answer the hello is set aside before it sees the password, and one that fails after is `kdf_failed`, not retried. The worker still answers version 1 (`KDFRequest`).

The format, the profiles and the test vectors are specified in SPEC.md at https://github.com/thehappieco/kit, at the tag matching this version. Releases are GitHub release assets, pinned by integrity; the package is not published to a registry.
