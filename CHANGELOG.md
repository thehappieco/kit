## v0.5.0

The release date is the tag's.

- SPEC 11.14, serving the callback: `no-referrer` is acceptable when the page's same-origin POST to its server sets its own `referrerPolicy` (for example `'same-origin'`); without it Firefox and WebKit send `Origin: null` (the platform's request, tested by Mailie in Chromium 153, Firefox 155 and WebKit 26.6). Wording only.
- The platform profile refuses a relying party id that ends in a number, as the WHATWG URL Standard's host parser decides it (SPEC section 11.16), as the platform's server does since `75b6b94`: besides an all-decimal last label, which v0.4.0 refused, a last label of `0x` and zero or more hex digits, such as `0x7f000001`, `1.2.3.0x4` or `id.0xff`, which a browser reads as an IPv4 address or refuses, so no passkey can exist for it. `id.0x1g`, `id.00x1` and a hex first label still pass, and so does an `xn--` label that is not valid Punycode, which the rule, like the platform's, does not check, and on which engines disagree (Firefox and Node refuse `xn--a`, Chromium and WebKit keep it). `ValidRPID`, `isRPID`, and through them `PRFSalt`, `PasskeyWrapKey`, the passkey wraps and their TypeScript twins, refuse it with `wrap`. This is the release's one refusal of input v0.4.0 accepted. The checker, written as the standard's steps, is exported from the generic passkey module (Go `passkey.EndsInANumber`, TypeScript `endsInANumber`), whose own functions, like Wappie's profile, check no spelling of the relying party id: a product checks its id where it is configured.
- Vectors: the platform's `rp-id-ends-in-number.json` (29 cases, 17 must fail, 8 of them the hex forms v0.4.0 accepted), byte for byte from platform commit `75b6b94`, beside the thirteen earlier files, which do not change. Vectors, written by the console's two modules at that commit with the header patched (`vectors/wappie/_generators/run-cloud.sh`, `make vectors-cloud-regen-check`), since the console has not committed the header itself: `wappie/golden/platform-wrap-go.json` (55 cases, 31 must fail) and `platform-wrap-ts.json` (22, 10), and the console's own file, rewritten by its own test, as `wappie/legacy/platform-wrap-vectors.json`, which both languages also write again byte for byte. `kit/wappie-platform-wrap-{go,ts}.json` round-trip fresh wraps between the languages.

- New in Go: the account scheme, the passkey wrap and JCS, pinned to Wappie's TypeScript by its vectors, with ECMAScript's `trim`, `toLowerCase` and `toUpperCase` where Wappie's wire bytes depend on them.
- Changes from Wappie that change no byte of any output that opens today: errors carry codes; TypeScript checks that ids are 16 bytes and that epochs and content key ids fit their fields (an epoch of 65536 used to seal an envelope nobody could open), and that a generated key's PKCS#8 export has the expected form; Go reports a low-order encapsulated key as `authentication` like every other direct-mode failure; `hpke.importArchiveKey` is `importPrivateKey`; the `Sealer` takes a clock option instead of a test hook; `KeyStore` no longer declares `CountSeal`, which the `Sealer` never called.
- Checks Wappie did not have, each refusing only input that never produced openable data:
  - TypeScript HPKE rejects an all-zero X25519 output itself (RFC 9180 §7.1.4) instead of relying on WebCrypto: a forged grant under a low-order encapsulated key does not open, and nothing is sealed to a low-order public key (`invalid_key`, also in Go). The vectors carry real forgeries, and the TypeScript tests also run them on an engine that lets the zeros through.
  - The account profile's bounds can fix the salt's length (the platform's policy: 16 bytes).
  - A passkey wrap refuses an empty AAD (`bad_aad`); Wappie's JSON AADs are built with JCS, so a binding with no JSON text (a lone surrogate, invalid UTF-8) is refused rather than escaped, and Go's `PasskeyAAD` returns an error instead of nil.
  - The prepared password, the master key and the raw wrap key are zeroed after a derivation, in the worker too; so are the PKCS#8 buffers `hpke` builds to import a private key and exports to generate one.
- Vectors: Wappie's six fixtures byte for byte, golden vectors from Wappie's Go and TypeScript, vectors for v0.2.0's attestation, keychain and derived records, and the kit's own vectors in both directions.
- CI runs the TypeScript vectors in Chromium, Firefox and WebKit, and a release is published only when every job passes on a commit of `main`, with the Node and npm versions pinned.
